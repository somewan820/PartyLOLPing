# PartyLOLPing 局域网验收矩阵

这份矩阵记录两台或三台真实 Mac 的验收结果。自动化脚本只运行 fake/in-memory
transport 测试，不需要屏幕录制授权，也不会保存屏幕帧、邀请码或昵称历史。

## 运行方式

```zsh
# 纯逻辑回归（不访问真实屏幕）
zsh scripts/test.sh

# 按范围运行 fake transport 检查
zsh scripts/integration-check.sh --host --guest --media

# 构建并检查可签名 app bundle
zsh scripts/build.sh
```

`integration-check.sh` 输出的 `test_duration_s` 是 fake 测试耗时；首帧和 Ping
P95 的真实值必须在两台 Mac 上完成下方手工验收后填写。诊断输出只包含协议范围、
连接状态和计数摘要。

## 两机/三机功能矩阵

每行填写 `通过`、`失败` 或 `阻塞（原因）`，并附简短观察结果。不要把邀请码、
完整昵称或屏幕截图写进日志；失败示例使用脱敏的成员编号。

| 场景 | 预期结果 | A | B | C | 观察/错误状态 |
| --- | --- | --- | --- | --- | --- |
| 同 Wi‑Fi 创建/加入 | 6 位邀请码加入成功，成员状态收敛 |  |  |  |  |
| Wi‑Fi ↔ 以太网 | 同一子网可发现并加入 |  |  |  |  |
| 指定窗口共享 | 仅选定窗口出现在观看端，首帧 < 5 秒 |  |  |  |  |
| 外接屏窗口 | 可枚举并持续预览 |  |  |  |  |
| 窗口关闭/最小化 | 进入可理解的暂停/停止状态，可恢复 |  |  |  |  |
| 定向 Ping | 目标成员收到一次远程 HUD，发送端有发送状态 |  |  |  |  |
| 广播 Ping | 所有已启用远程 Ping 的成员收到 HUD |  |  |  |  |
| 默认静音 | 新成员远程 Ping 声音默认关闭 |  |  |  |  |
| 成员/全局静音 | 静音立即生效，视觉 HUD 仍可见 |  |  |  |  |
| 房主移除成员 | 被移除端断开并不能继续发 Ping/看媒体 |  |  |  |  |
| 房主退出 | 房间结束，剩余端收到结束状态 |  |  |  |  |
| 房主崩溃 | 访客进入断线状态并停止媒体 |  |  |  |  |
| 睡眠/唤醒 | 连接状态可理解，重连后可重新加入 |  |  |  |  |

## 性能与隐私门槛

| 指标 | 目标 | 实测 |
| --- | --- | --- |
| 1→5 fan‑out 持续时间 | 30–60 分钟 |  |
| 首帧时间 | < 5 秒 |  |
| Ping 延迟 P95 | < 1 秒 |  |
| 持续内存增长 | 无持续增长 |  |
| 房间 UI/轮盘可用性 | 共享不阻塞 |  |
| 帧丢弃/重连 | 记录计数，解释异常 |  |

验收完成后确认最终 bundle：`CFBundleIdentifier` 为
`local.allentu.PartyLOLPing`，包含 `NSLocalNetworkUsageDescription`、
`NSScreenCaptureUsageDescription`、`_partylolping._tcp` 与
`_partylolping-media._tcp` 两个 Bonjour 服务，并带有网络 client/server
entitlements。媒体帧必须通过 `MediaSecureSession` 的 AEAD 通道传输。
